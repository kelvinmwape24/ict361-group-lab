Rule enforced:
- operation_id is PRIMARY KEY in operation_receipts.
- payload_hash stored with each receipt.
- Same operation_id + same payload_hash -> return stored result (idempotent).
- Same operation_id + different payload_hash -> 409 OPERATION_ID_REUSED.
- New operation_id -> apply change and insert new receipt.

Why this prevents duplicate effects:
Even if the response is lost (network interrupted, server killed, client retry),
the client's retry finds the stored receipt and returns the same result without
re-applying the mutation. Only one record change occurs, and only one receipt exists.

Verification:

- student version after retry: 3 (not 4)
- Server rejected operation_id reuse with different payload: OPERATION_ID_REUSED
